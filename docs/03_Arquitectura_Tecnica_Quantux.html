Capa y Tecnología Rol Funcional en la Operación Justificación Técnica y Beneficio para el Negocio
Frontend UI
HTML5 / Modern JS		 La Pantalla Web Centralizada que operan profesionales de la salud y soporte. Cero Instalación: Abre al instante en cualquier navegador sin requerir permisos de IT ni descargas pesadas. Diseño Cockpit en 3 columnas que evita la dispersión de pestañas.
Backend API
FastAPI / Python 3.11+		 El Cerebro y Recepcionista que procesa tickets y calcula prioridades. Velocidad y Auditoría: Tiempo de respuesta < 10 ms (vital en incidentes críticos asistenciales). Genera automáticamente documentación interactiva (/docs) para auditar cada función.
Validador de Reglas
Pydantic v2		 El Inspector de Calidad que audita cada dato antes de ingresar. Cero Datos Corruptos: Rechaza datos incompletos y bloquea el pase a "Resuelto" si no se redacta una solución técnica fundamentada (≥ 8 caracteres).
Persistencia Relacional
SQLite 3 + SQLModel		 El Archivador Digital Seguro donde residen tickets y auditoría. Cero Costo MVP + Escalabilidad: Cero costo de licencias de servidor en fase piloto. Si el volumen crece a 100.000 tickets, se migra a PostgreSQL sin cambiar lógica de negocio.

5. Matriz de Prioridad (P = I × U) y Reglas de Transición

Matriz 2D de Prioridad (P = I × U)

Urgencia \ Impacto CRÍTICO ALTO MEDIO BAJO
CRÍTICA P1 (Crítica) P1 (Crítica) P2 (Alta) P3 (Media)
ALTA P1 (Crítica) P2 (Alta) P3 (Media) P4 (Baja)
MEDIA P2 (Alta) P3 (Media) P3 (Media) P4 (Baja)
BAJA P3 (Media) P4 (Baja) P4 (Baja) P5 (Planif.)

Reglas Clave de Gobernanza FSM

NUEVO ➔ ASIGNADO / EN_CURSO
Requiere fijar operador responsable y nivel (N1/N2/N3) o autoasignación directa.
EN_CURSO ➔ RESUELTO
Exige notas técnicas ≥ 8 caracteres y tipificación de si es solución provisoria (Workaround).
RESUELTO ➔ CERRADO
Conformidad final. El ticket se vuelve inmutable y se cierra la auditoría.

Quantux Salud DOC-ARC-003: Catálogo Exhaustivo de Endpoints REST

6. Catálogo Completo de Endpoints REST (14 Interfaces) OPENAPI 3.0

Verbo Ruta del Endpoint Request Payload / Params HTTP Status Regla de Negocio y Efecto
POST /api/v1/auth/login { username, selected_role } 200 / 401 / 403 Valida credenciales y rol. Devuelve perfil y vista de aterrizaje autorizada.
GET /api/v1/auth/switch-role/{role} Path: role (SOL/SOP/ADM) 200 / 404 Alterna en 1 clic el rol activo del usuario para pruebas rápidas en el Cockpit.
GET /api/v1/platforms Ninguno 200 OK Retorna el catálogo de las 9 plataformas de salud oficiales.
GET /api/v1/institutions Ninguno 200 OK Retorna el listado de los 14 clientes institucionales activos.
GET /api/v1/calculate-priority Query: impact, urgency 200 OK Calcula dinámicamente la prioridad P1..P5 mediante la matriz P = I × U.
GET /api/v1/tickets Query: status, platform, inst, q 200 OK Bandeja de tickets filtrada y ordenada por criticidad (P1 ➔ P5).
GET /api/v1/tickets/{id} Path: id (TICK-YYYYMM-XXXX) 200 / 404 Detalle completo del ticket, hilo de comentarios y log de auditoría.
POST /api/v1/tickets Paso 1: { title, desc, plat, inst, I, U } 200 / 400 Crea ticket en `NUEVO`, genera ID correlativo y traza inicial de auditoría.
PATCH /api/v1/tickets/{id}/assign Paso 2: { assignee, support_level } 200 / 400 Asigna operador. Si estaba en `NUEVO`, pasa automáticamente a `ASIGNADO`.
PATCH /api/v1/tickets/{id}/status Paso 3: { new_status, reason } 200 / 400 Avanza estado operacional (ej. a `EN_CURSO` o pausa por espera de datos).
POST /api/v1/tickets/{id}/resolve Paso 4: { notes, is_workaround } 200 / 400 Pasa a `RESUELTO`. Exige notas ≥ 8 caracteres y tipificación de solución temporal.
POST /api/v1/tickets/{id}/close Paso 5: { closed_by, feedback } 200 / 400 Cierre definitivo. Valida estado `RESUELTO`. El ticket pasa a ser inmutable.
POST /api/v1/tickets/{id}/comments { author, message, is_internal } 200 / 404 Registra mensaje en el hilo o nota interna privada para soporte.
GET /api/v1/users/operators Ninguno 200 OK Lista operadores de soporte disponibles para asignación en el Cockpit.

7. Decisiones de Arquitectura y Criterios de Gobernanza

1. ¿Por qué este diseño garantiza el éxito del MVP de 5 semanas?
"Porque desacopla la lógica de negocio de la infraestructura: permite operar al 100% de inmediato sin costos de servidores ni demoras de IT, con soporte nativo para migrar a PostgreSQL y nubes corporativas en cualquier momento."
2. ¿Cómo se audita la calidad del soporte clínico?
"Mediante el bloqueo automático de cierres sin resolución fundamentada y el registro permanente en la Caja Negra inmutable de auditoría (ticket_audit_log)."
